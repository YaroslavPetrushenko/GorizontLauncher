# Как загрузить и поменять сборку (моды, конфиги)

Сборка — это один релиз на GitHub с тегом `pack-X.Y.Z`, в котором лежат два файла: `modpack.zip` и `modpack.sig`.
Игроки получают её сами: лаунчер при запуске смотрит последний `pack-*` релиз и, если версия новее, скачивает и ставит.
Ставить заново сам лаунчер не нужно.

## Что нужно один раз

- Закрытый ключ подписи: `%USERPROFILE%\.gorizont-keys\pack-signing.key`. Без него сборку не подписать, а лаунчер
  отказывается ставить неподписанные. Ключ нельзя класть в репозиторий и терять: публичная часть вшита в лаунчер.
- Python с пакетом `cryptography` (`pip install cryptography`) и установленный `gh` (GitHub CLI), вход через `gh auth login`.

## Шаги

### 1. Подготовить папку сборки

Это обычная папка с содержимым игры: `mods\`, `config\`, `resourcepacks\`, `shaderpacks\` и всё остальное, что должно
быть у игрока. Например, `E:\GorizontPack`. Папку `versions\` в неё класть не нужно, лаунчер ставит клиент сам.

Чтобы **поменять моды**: добавьте, удалите или замените `.jar` в `E:\GorizontPack\mods`. Так же с конфигами.
Моды только для 1.21.1 и NeoForge.

### 2. Выбрать новую версию

Версия всегда выше предыдущей (`2.6.0` → `2.6.1` или `2.7.0`). Тег и версию повторять нельзя: опубликованные релизы
неизменяемы, поправить файлы в уже выпущенном релизе нельзя, нужен новый номер.

### 3. Собрать архив

```powershell
.\tools\New-ModpackZip.ps1 -Source "E:\GorizontPack" -PackVersion "2.7.0" -Output "modpack.zip"
```

Скрипт кладёт в архив `manifest.json` (Minecraft 1.21.1, NeoForge 266). Если меняется версия NeoForge, добавьте
`-LoaderVersion 267` (число после `21.1.`).

### 4. Подписать

```powershell
python tools\sign-modpack.py --zip modpack.zip
```

Рядом появится `modpack.sig`.

### 5. Выпустить релиз

Оба файла прикрепляются **сразу при создании релиза**:

```powershell
gh release create pack-2.7.0 modpack.zip modpack.sig --title "Сборка 2.7.0" --notes "Что изменилось: ..."
```

Если создать релиз без файлов, а добавить их потом, GitHub откажет, потому что опубликованный релиз неизменяем.
Если ошиблись, выпустите следующий номер (`2.7.1`), а неудачный релиз можно удалить.

## Что происходит у игрока

- При следующем запуске лаунчер видит новую версию, скачивает архив, проверяет подпись и ставит сборку.
- Моды, которые игрок скачал сам в «Доп. модах», на время обновления откладываются в сторону и возвращаются после установки.
- Моды старой сборки, которых нет в новой, убираются, чтобы не было двух версий одного мода.
- Лишние `.jar`, которых нет ни в сборке, ни среди скачанных игроком, лаунчер переносит в `mods-removed`. Исключение: мод,
  который опознан на Modrinth как подходящий для 1.21.1 и NeoForge, добавляется в «Мои моды».

## Частые вопросы

- **Игроки не получили обновление.** Проверьте, что в релизе оба файла и тег начинается с `pack-`. Версия должна быть
  выше текущей, а релиз не должен быть черновиком.
- **Ошибка подписи.** Архив подписан не тем ключом или изменён после подписи. Соберите и подпишите заново.
- **Заблокировать мод игрокам.** Это не сборка: войдите в лаунчер под аккаунтом модератора, в «Доп. моды» нажмите
  «Заблокировать» на нужном моде. Для модов из самой сборки блокировка не нужна.
- **Новая версия лаунчера** (не сборки): тег `launcher-vX.Y.Z`, собирается на GitHub для Windows, macOS и Linux.
